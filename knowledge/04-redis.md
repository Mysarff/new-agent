# Redis 热点失效与缓存穿透

模拟内部知识：星河工单列表支持查询缓存。所有方案都需要实际负载验证。

## 缓存击穿与雪崩
单个热点键到期时，大量请求同时访问数据库，可表现为缓存命中率突然降低与数据库查询量上升。多个键在相近时间到期会形成更广的瞬时负载。对照键级别访问、到期分布、数据库压力与发布时间，避免把所有延迟升高都归因于缓存。

## 缓存穿透
大量请求查询不存在的工单时，即使 Redis 正常也会持续访问数据库。检查请求参数分布和是否来自重复无效对象。可评估短期空值缓存或存在性过滤，但要分析新增数据可见性、误判和更新机制。不能用一条规则拒绝所有新工单。

## 一致性与恢复
缓存恢复不等于数据正确。发布后要核验读写路径、租户隔离、过期策略和失效事件。清空整个缓存可能触发数据库负载激增；助手只能说明风险与验证步骤，不能执行清空。示例没有真实 Redis 地址或访问凭证。
