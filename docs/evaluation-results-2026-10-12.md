# 2026-10-12：计划执行、回答完整性与响应速度

这是开发过程中的真实模型/API 联调记录。每次试验都保存问题、答案、证据、执行轨迹和耗时，包括失败项；各阶段代码不同，不能合并成一项“模型准确率”。模型为本机已配置的 Qwen3.7 Flash，使用四个独立 A2A 专家与真实 MCP 工具。

## 性能对照（页面故障反馈补丁之前）

原页面示例：**“明天去陕西西安，天气怎么样？如果下雨，怎么安排？”**，查询日期为 2026-10-13。

| 指标 | 旧协调器 / 服务商默认思考 | 新计划流程 / 关闭思考 |
| --- | ---: | ---: |
| 完整响应耗时 | 154.500 秒 | 24.234 秒 |
| 模型请求 | 10 次 | 8 次 |
| 业务工具调用 | 3 次 | 4 次 |
| 服务商返回的总 Token | 51,747 | 32,451 |
| 自动执行判据 | 通过 | 通过 |

本次单对照耗时减少约 **84.3%**。两种流程都保留天气和条件备选查询，新流程明确提示预报不确定性。对照包含计划执行、精简交接和关闭思考三项变化，不能将效果全部归因于计划执行。它没有测量并发吞吐、流式首字时间或人民币费用；一次对照也不能代表稳定 P95。

原始记录：[JSON](../reports/planned-final-paired-2026-10-12.json) / [CSV](../reports/planned-final-paired-2026-10-12.csv)。前面旧流程同句实测为 81.656 秒，说明外部服务和模型生成存在明显波动，不能只选择最慢基线声称稳定提速倍数。

## 本次修复

- 同一次模型请求生成完整行程和任务计划，按能力描述选专家。所有计划任务按依赖顺序执行，假设备选不能因预报无雨就取消；一般建议和澄清可不委派专家。
- 专家查询后做简短交接，最终一次结构化生成合并来源核对和答案整理，减少协调器反复写长答案。原始证据保留，仅去除完全相同的重复字段。
- 最终答案必须逐项对应任务，引用限于实际证据；缺项或违规最多修正一次。已列入计划但失败的同一任务不作为新遗漏重复委派。未接入票务的正常业务状态保留具体说明。
- 温度、概率、日期等天气事实直接用预报接口数据呈现，附预测不确定性提示。针对已发现的“不会下雨”“无需防雨”等措辞加小范围检查；这不是能识别所有变体的语义证明。
- 相对日期使用当前用户时区的日期参照，提示模型继承地点、替换查询日期，避免从上一轮旅行日期继续累加。数值型上下文字段保留无损格式修复和范围校验。
- 修正最终生成同时要求“不要调用工具”和“通过工具提交”的冲突。未接入工具没有证据时，引用数组必须为空；知识核验日期从证据元数据补充。
- 模型只对连接建立失败重试一次，不自动重放读取超时或业务工具。A2A 服务错误附不含敏感值的失败阶段和异常类型；早期通用错误的具体原因无法事后确认。

页面默认使用新流程，本机 `.env` 已设置关闭当前模型的思考模式。仓库 `.env.example` 保持留空，其他模型部署者需先确认支持该参数；页面可沿用配置或切换思考模式，覆盖与来源检查始终保留。

全部阶段索引及观察见 [validation notes](../reports/planned-validation-notes-2026-10-12.json)，原始文件未删除或覆写为成功：

| 阶段报告 | 发现的问题 |

| `planned-pilot` | 31.422 秒，旧自动规则判通过，但答案称备选“暂不触发”；这是已确认的自动判据漏检，不算语义成功 |
| `planned-repeat` | 一次未查地点、一次最终校验失败；两次均保留失败 |

| `planned-final-controls` | 6 项中 4 项通过；票务虚构引用、日期追问不必要澄清且保留错误日期 |

| `planned-final-paired` | 最终新旧流程同示例各 1 次，两者通过执行判据 |

开发期间观察失败后修改提示和约束，因此这是调试回归证据，不是独立测试集的泛化成绩。模型仍可能漏识别需求、生成证据不支持的描述或多查工具；失败会消耗时间与 API 费用。没有将自动执行成功率当成答案正确率。

程序回归：`python -m unittest discover -s tests -q` 共 **184 项，163 通过、21 跳过**。跳过项为 MySQL 集成测试，本次未改数据库层；不将其报告为本次通过。新增测试覆盖必需查询、假设备选、缺项修正、未知引用、跨任务引用、失败与预算、多个天气来源、核验日期、连接重试和页面模式选择。

复现命令及指标定义见 [evaluation.md](evaluation.md)。真实测试会调用配置的模型和外部 API。

## 页面验收追加记录

首次页面提交原示例用时 40.0 秒（9 次模型、4 次业务工具、44,728 Token），地点接口未返回有效数据，网页搜索后最终结构化结果连续两次未通过 Schema 校验。该次按失败保留，不算在上面的成功示例中。原错误只记录 ValidationError，无法事后确定具体字段；已补充不含拒绝值的字段/约束反馈，便于模型在一次修正内定位问题。

同时修复失败展示：最终整理不通过时，仍可显示已经取得的原始预报，并逐项标记剩余任务未完成，绝不展示不合格的模型草稿。已通过的逐项任务仍不等于整轮通过，原失败检查和耗时照常保留。该补丁只影响校验失败的反馈与展示，上方性能对照未重新测量此补丁的提速效果。

第二次页面复测为 31.7 秒（9 次模型、4 次业务工具、38,590 Token），缺少必填根字段在一次修正后恢复，显示天气和地点候选及来源。随后补充条件任务的备选标签，以及缺失字段名称反馈；没有放宽来源校验。相关分支 17 项回归通过。

最终页面复测为 **25.2 秒**，8 次模型请求、4 次业务工具调用、30,787 Token。页面同时展示真实预报及不确定性、明确标注的雨天备选、来源链接和场所待核实条件；这次没有最终校验重试。前两次页面尝试及失败仍保留在 validation notes，不混入 5/5 命令行执行验收分母。
